Composition

Program.cs builds a minimal API host and maps three routers plus the built-in identity endpoints. Service lifetimes are deliberate and worth knowing before changing them.

Registration Lifetime Note
IGameService → GameService Singleton Holds live bracket and vote-ledger state for every in-flight game.
IPlayerManager → PlayerManager Scoped Per-request player persistence.
IUserManager → UserManager Scoped Per-request user operations.
ApplicationDbContext Scoped EF Core over SQLite.
IEmailSender → DisabledEmailSender Transient Stands in while no mail infrastructure exists; identity confirmation mail is inert.

Enums serialize as strings via JsonStringEnumConverter, so clients see "LOBBY_WAITING" rather than an ordinal. CORS allows any localhost or 127.0.0.1 origin in Development and only AppConstants.ClientUrl otherwise, with credentials permitted in both cases so the identity cookie flows.

GameService is a singleton holding in-memory bracket state. Restarting the API discards the progression of any game currently in flight. This is fine for a party running on one machine, and it is the constraint to revisit before any multi-instance or restart-tolerant deployment.

How identity is enforced

Enforcement is not uniform, and the difference matters when reasoning about what an unauthenticated caller can do. Three distinct mechanisms are in use:

  • RequireAuthorization — the endpoint is gated by the authorization middleware.
  • Claims check — the handler reads ClaimTypes.NameIdentifier itself and returns 401 when it is absent.
  • Open — no identity check in the handler and no authorization filter.

Most /Games routes are open. Only AddPlayer and SubmitMatchVote verify a caller. Creating a game, starting a game, and reading bracket, current match, player list, or flow state all succeed without a session. The whole /Players router is open as well. That is accurate as of this writing rather than a recommendation — it is recorded here so the gap is visible.

Game routes

Mapped by GameRouter under the /Games group.

Method Route Identity Purpose
POST /Games/CreateGameWithMode Open Creates a game from CreateGameOptions; returns the new game id and mode.
POST /Games/GetPlayersInGame/{gameId} Open Returns currentPlayers for the game, or 404 if unknown.
POST /Games/AddPlayer/{gameId} Claims check Binds the caller's user id to a Player and adds it to the game.
POST /Games/StartGame/{gameId} Open Generates the bracket and broadcasts GameStarted to the game group.
GET /Games/GetBracket/{gameId} Open Returns a BracketSnapshotResponse for rendering.
GET /Games/GetCurrentMatch/{gameId} Open Returns the active CurrentMatchResponse when one exists.
GET /Games/GetFlowState/{gameId} Open Returns the authoritative GameStateResponse the client routes on.
POST /Games/SubmitMatchVote/{gameId} Claims check Records one participant vote and commits the match on consensus.

User routes

MapIdentityApi<ApplicationUser>() supplies the stock identity endpoints (register, login, refresh, confirmation, password management). UserRouter adds domain endpoints under /users.

Method Route Identity Purpose
POST /users/login Open Signs a user in and establishes the session cookie.
GET /users/demo-credentials Open Development only — returns the seeded demo username and password.
GET /users/session RequireAuthorization Reports the signed-in identity for session validation.
POST /users/logout RequireAuthorization Signs the user out and releases their game association.

Sign-in is intercepted by ConfigureApplicationCookie's OnSignedIn event, which calls AppSetup.HandleUserSession to attach a server-side session record to the user.

Contracts

All defined in Models/Contracts/BracketContracts.cs as sealed records.

Requests

ReportMatchRequest is declared but no route currently binds it; direct result reporting was superseded by the vote flow.

Responses

                        int VoteCount, Guid? CommittedWinnerPlayerId)

BracketMatchView(Guid MatchId, BracketLane Lane, int Round, int MatchNumber,

BracketSnapshotResponse(Guid GameId, BracketMode Mode, bool GameStarted,
                        bool IsGrandFinalResetRequired,
                        IReadOnlyList<BracketPlayerView> Players,
                        IReadOnlyList<BracketMatchView> Matches)

CurrentMatchResponse(Guid GameId, Guid MatchId, BracketLane Lane,
                     int Round, int MatchNumber, Guid PlayerOneId, Guid PlayerTwoId)

GameStateResponse(Guid GameId, GameState State, bool GameStarted, Guid? CurrentMatchId,
                  Guid? CurrentMatchPlayerOneId, Guid? CurrentMatchPlayerTwoId)

NextMatchForWinner and NextMatchForLoser are what make the snapshot self-describing: the client can draw connectors without knowing the seeding rules, and the same shape serves both elimination modes.

Bracket engines

IBracketEngine has two implementations under Services/Brackets/. BracketRuntimeModels.cs holds the mutable runtime state that the read-only view records above are projected from.

SingleEliminationEngine

One lane. A loss eliminates. Byes fill an incomplete first round.

DoubleEliminationEngine

Winners and losers lanes, with GRAND_FINALS and a conditional GRAND_FINALS_RESET when the losers-bracket player takes the first grand final. IsGrandFinalResetRequired on the snapshot reports that condition.

Errors and validation

Utilities/Exceptions/ holds domain exceptions used instead of bare throws, including BracketGenerationException, GameNotFoundException, PlayerNotFoundException, RoundMismatchException, and validation exceptions per entity. Utilities/ModelValidators/ holds GameValidator, PlayerValidator and UserValidator.

Vote handling is the exception to exception-driven flow: SubmitMatchVoteStatus reports refusal as data on a successful response rather than as a thrown error, because refusal is expected traffic — two phones racing the same button is normal, not exceptional.
